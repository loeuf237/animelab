# AnimeLab v0.1.5 — New identity, source verification and shared-server hardening

## Major Changes

### New AnimeLab branding and compatible migration

The new flask-and-anime logo is used by Android, desktop launchers, the web interface and PWA icons. Modern `ANIMELAB_*` settings take precedence while older `ANIMAN_*` environment settings remain supported. Browser preferences migrate progressively without removing their older values. Existing private databases, account directories, Android package identity and production signing certificate are preserved.

### Source verification and reliable browsing

Source requests use the shared HTTP client for normal traffic and can request an interactive browser verification when required. Supported native WebViews exchange cookies with the engine, and active requests resume after verification. An installed Chromium-compatible executable can be configured in the launcher, settings or startup arguments. Remote shared-server clients retain their device isolation and cannot open a browser on the operator's machine.

### Shared-server authentication and media boundaries

Successful sign-ins no longer consume a shared login quota. Failures are limited per account and peer, while password calculations have bounded concurrency. Operators can explicitly trust HTTPS proxy addresses and approve additional media CDN domains. Media proxies validate their destinations, redirects and HLS child URLs while retaining viewing access for accounts without download permission.

## Added

- **(Deployment)** Repeatable `--trusted-proxy IP_OR_CIDR` and `ANIMELAB_TRUSTED_PROXIES` for forwarding headers from explicitly trusted proxies. Forwarding headers remain ignored by default.
- **(Media)** Shared-server destination allowlist for images, subtitles, streams, HLS segments and AES keys; additional operator-approved domains through `ANIMELAB_MEDIA_DOMAINS`.
- **(Authentication)** Self-describing `scrypt$n$r$p$salt$key` password records and automatic upgrades of historical hashes after a successful login.
- **(WebUI)** Content-Security-Policy on Vue pages and assets, with local scripts and support for HLS blob workers, HTTPS media and application fonts.
- **(Verification)** Configurable installed Chromium path and headless mode, with explicit capability and browser-session handling.

## Changed

- **(Authentication)** Only failed authentications consume the failure budget. Successful requests clear their own failures; invitation/recovery failures do not lock unrelated accounts out. Temporary hashing capacity returns HTTP 503 with a short retry delay.
- **(Configuration)** Modern environment names take precedence over compatible legacy aliases. Controlled worker environments keep both names synchronized.
- **(Storage)** New default series folders use AnimeLab; explicitly configured paths and existing task/file locations are retained. Android video exports use the platform's Movies/AnimeLab location.
- **(Branding)** Updated application icons, adaptive Android icons, desktop ICO/ICNS/PNG assets, favicon, PWA maskable icons and README artwork.
- **(Android)** Version 0.1.5, version code 218, existing application ID and production signing identity retained for compatible updates.

## Fixed

- **(Shared access)** Repeated successful logins behind one reverse proxy no longer exhaust a server-wide authentication quota.
- **(Security)** Cached media, redirect destinations and HLS keys cannot bypass the shared-server media domain policy.
- **(Passwords)** Changing the configured hash work factor no longer invalidates existing versioned records; legacy records retain their original parameters during verification. Concurrent administrator resets take precedence over hash upgrades.
- **(Anime-Sama)** Search results retain proper titles and expand supported catalogue entries into distinct seasons/releases rather than a merged title containing navigation labels.
- **(WebUI)** Rounded search-dialog Close button and localized authentication-capacity/failure messages.
- **(Tests)** PWA HTML integration is skipped when the Vue build is absent; the complete CI suite still requires and checks the compiled interface.

## WebUI

The compiled Vue interface is bundled in every package. Source verification, search-season selection, account controls and branding use the same tagged source across Android and desktop.

Extract the **entire desktop archive**, then open the launcher. The Python runtime, compiled web interface, FFmpeg and ffprobe are bundled; Node.js is not required on the user’s computer. Android requires an ARM64 device running Android 10 or later. **macOS packages are unsigned and not notarized.** Native Linux WebViews require compatible system libraries; installed-browser mode remains available. Automated tests do not certify every physical device or external source.

**Updating:** stop the old desktop server and extract into a separate directory, preserving your existing user data. A compatible production-signed Android installation can be updated without uninstalling. The progressive naming migration does not relocate existing private databases automatically.

**Shared deployments:** declare the actual HTTPS proxy IP/CIDR explicitly to distinguish client addresses. Configure that proxy to overwrite incoming forwarding headers. New source CDNs may require operator approval through `ANIMELAB_MEDIA_DOMAINS`; restart active account engines after changing it. See the deployment guide above.
