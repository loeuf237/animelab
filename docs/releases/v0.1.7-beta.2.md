# AnimeLab v0.1.7-beta.2 — Android extension UX, flicker & private storage fixes, native UI redesign

## Major Changes

### Android extension APK flicker fix & Mihon/Aniyomi-style installation UX

Eliminates the endless screen-blinking loop triggered by stale Android `PackageInstaller` sessions across restarts and improves native APK extension installation and updates (`ExtensionPackages.kt`, `ExtensionBridge.kt`, `AndroidExtensionsPanel.vue`, `ExtensionsView.vue`). Active installations now reconcile stale `PackageInstaller` sessions with explicit grace-period and timeout bounds, poll silently in the background without toggling loading states or re-rendering unchanged package lists, and provide Mihon/Aniyomi-style one-tap install/update actions, inline step progress, `POST /api/extensions/android/operations/{operation_id}/confirm` prompt reopening, permission guidance and signature-conflict uninstall recovery while preserving explicit `versionCode` + SHA-256 signer trust approval.

### Android private storage cleanup & complete permissions overview

Resolves multi-hundred-megabyte private App Data growth on Android after media export or removal (`android_runtime.py`, `NativeHooks.kt`, `download_manager.py`, `extension_service.py`, `AndroidStorageSettings.vue`). Verified `MediaStore`/SAF exports now release their private staging copies automatically (`export_completed` → `_release_private_paths`), task deletions (`remove_task`), history clearing (`DELETE /api/history`) and startup GC (`startup_android_storage_cleanup` with `exportedCopyExists` verification) purge private copies safely while protecting active/paused/pending-export tasks, and completed staged `.apk` archives are pruned (`prune_staged_apks`). Settings → Storage now exposes all four Android permission cards (`Folder`, `Notifications`, `APK extension installation`, `Background downloads`), explains Scoped Storage (`SAF`/`MediaStore`) vs legacy global Storage access, and adds a one-tap `Free private storage` cleanup button (`/api/system/android/storage/cleanup`).

### Native cross-platform UI redesign, progressive catalogue streaming & Android diagnostics

AnimeLab adapts its chrome, spacing, navigation and dialogs to the host platform across Android, desktop and browser environments (`MainActivity` edge-to-edge rendering, `NativeUiBridge` bar/haptic synchronization, five-tab bottom navigation + `More` hub, desktop light/dark palette synchronization and accessible in-app confirmation dialogs). Large source listings stream incrementally over NDJSON via `/api/sources/{source_id}/catalogue/stream` with shimmer placeholders, Android update detection handles both `v*` and `android-v*` releases cleanly (`WebViewTransport` popup handoff), `CrashReporter` + `GET /api/diagnostics/export` + `POST /api/diagnostics/report` collect structured diagnostics into `Downloads/AnimeLab`, and the default VoirAnime base URL is migrated to `https://voiranime.cx`.

### Experimental Android APK runtime (Beta)

This beta keeps the **experimental Aniyomi/Anikku APK extension runtime** enabled (`version 0.1.7`, version code **224**, package `com.animan.app` and existing production signing certificate preserved for seamless in-place updates).

## Added

- **(Android Extensions)** `POST /api/extensions/android/operations/{operation_id}/confirm` endpoint and `openConfirmation()` / `confirmOperation()` session recovery in `ExtensionPackages.kt` and `ExtensionBridge.kt`, plus Mihon/Aniyomi-style install/update controls, inline progress, permission prompts and signature-conflict uninstall flow in `AndroidExtensionsPanel.vue`.
- **(Android Storage)** Automatic post-export private staging copy cleanup (`android_runtime.py`), startup orphan/ghost garbage collection (`startup_android_storage_cleanup`, `NativeHooks.exportedCopyExists`), staged APK pruning (`prune_staged_apks`), `POST /api/system/android/storage/cleanup`, reclaimable storage reporting on `GET /api/system/android/storage`, and complete four-permission cards (`Folder`, `Notifications`, `APK extension installation`, `Background downloads`) plus `Free private storage` in `AndroidStorageSettings.vue`.
- **(UI)** Platform-aware design tokens, native OS styling sheets, bottom-sheet modal styles, `PosterCard`, responsive `SkeletonGrid`, five-tab `AppBottomNav` and the `MoreView` hub across Android, desktop and web.
- **(Streaming)** Incremental NDJSON catalogue stream endpoint (`/api/sources/{source_id}/catalogue/stream`) with live client consumption and shimmer loading placeholders.
- **(Android)** `NativeUiBridge` (system bar synchronization, haptic feedback, `MediaStore` diagnostics export) and `CrashReporter` (uncaught thread exceptions and WebView/engine startup failures persisted in private storage).
- **(Diagnostics)** `POST /api/diagnostics/report` client error ingestion, `recentErrorCount` and `lastCrash` fields in `GET /api/diagnostics/export`, global Vue/browser error listeners in `frontend/src/main.ts`, plus one-click summary copy and GitHub issue links in `DiagnosticsExport`.
- **(Docs)** Reusable Aniyomi/Anikku APK compatibility report added from PR [#44](https://github.com/loeuf237/animelab/pull/44) alongside refreshed showcase and contributor documentation.

## Changed

- **(Android)** Bumped `versionCode` to **224** (`versionName` `0.1.7`, default runtime `User-Agent` `AnimeLab/0.1.7`).
- **(Android Extensions)** Switched extension operation persistence to SQLite `ON CONFLICT(id) DO UPDATE` upsert (`animelab/services/android_extensions.py`) and updated `update_all_extensions()` with accurate Android pending confirmation status.
- **(VoirAnime)** Migrated the default VoirAnime base URL from `voir-anime.to` to `https://voiranime.cx` across source services, extractors and regression tests.
- **(Settings)** Fixed horizontal alignment and card padding in `AppUpdateSettings` so the application-and-updates panel lines up evenly with surrounding General settings cards.
- **(Desktop)** Updated `DesktopBridge`, Qt launcher widgets and panel styling so native desktop controls follow the selected theme and palette.
- **(CI)** Increased CI frontend and Python job timeout budgets from 15/20 minutes to 30 minutes to prevent runner cancellations.

## Fixed

- **(Android Flicker)** Fixed the continuous Android WebView/screen blinking loop after APK extension install/update attempts by reconciling stale `PackageInstaller` sessions with grace-period and timeout limits, siloing background polling from full-list reloads, and emitting extension changes only on real package or terminal operation transitions.
- **(Android App Data)** Fixed orphaned and exported media files plus finished staged APKs accumulating inside private Android App Data after `MediaStore`/SAF export, task removal or history clearing.
- **(Updates)** Fixed Android update detection across `android-v` and `v` tags (`per_page=10`, bounded request timeouts) and fixed `target="_blank"` release download links getting dropped by Android `System WebView` (`WebViewTransport`).
- **(Diagnostics)** Preserved `NativeUiBridge`, `CrashReporter` and `@JavascriptInterface` entry points under R8 minification in `proguard-rules.pro`, resolved `ANIMAN_DATA_DIR` fallback on Android when reading `last_crash.json`, and prevented stale `diagnostics` errors during crash inspection.
- **(Android Tests)** Updated `EmbeddedEngineTest` to recognize `.home-top-header` in the redesigned home view and to assert live `/api/diagnostics/report` and `/api/diagnostics/export` round-trips on physical ARM64 hardware.
- **(WebUI)** Added `mode="out-in"` to the root `<router-view>` transition so outgoing and incoming pages never mount simultaneously during in-app navigation.
