# AnimeLab v0.3.2

## Changes

- **Progressive Python Engine Boot (Android & Backend)**:
  - Decoupled Stage 0 startup dependencies (`animelab/sqlite_conn.py`, `animelab/request_origin.py`, `animelab/version_info.py`) and converted `animelab.models`, `animelab.routers`, and `animelab.services` packages to lazy PEP 562 exports.
  - Deferred heavy OpenAPI schema generation and cached per-route `TypeAdapter` instances in `ContractRoute`, converted heavy service/extractor singletons to lazy initialization, and excluded desktop-only modules (`animelab/desktop/**`) from Android builds.
  - Added staged ASGI route loading (`ProgressiveAppLoader` / `ProgressiveRouteMiddleware`, `/api/engine/readiness`) controlled by `ANIMELAB_PROGRESSIVE_BOOT=1` on Android, alongside lazy JNI bridge registration and background extension/storage warmup after Stage 0 readiness.
  - Measured on local Python 3.13 benchmarks (5-run median): loaded modules reduced from `794` to `538`, import time reduced by **63.9%** (`2168 ms` → `784 ms`), and first startup time reduced by **47.2%** (`2083 ms` → `1101 ms`).
- **Instant Android SPA Shell Before `Python.start()`**:
  - Packaged the built Vue 3 SPA bundle under Android `assets/spa/` (`syncSpaAssets`) and added `SpaAssetInterceptor` in `WebViewClient.shouldInterceptRequest` so `/spa*` and static assets render immediately on the `http://127.0.0.1` loopback origin before the embedded Python engine finishes booting.
  - Added `EngineHost` loopback readiness probing (`httpReady`, `awaitHttpReady`, startup timing metrics) and `AnimeLabAndroid.getEngineState()` / `animelab:engine-ready` / `animelab:engine-error` coordination so the Vue startup flow displays engine boot progress, defers i18n network calls until ready, and skips redundant Service Worker registration inside the Android WebView.
- **Non-Blocking Returning-User Startup**:
  - Returning users (`onboardingCompleted === true`) now enter the library immediately without waiting for remote update checks; available updates appear asynchronously through an actionable notification banner (`Update`), while first-run onboarding keeps pre-setup update checks and adapts cleanly to progressive Android boot.
