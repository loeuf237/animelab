# AnimeLab v0.1.3 — Native launcher and desktop tools

## Major Changes

### A native desktop launcher

AnimeLab now opens a compact configuration window before starting the engine. Choose your interface and settings, then click **Launch**. Closing the launcher leaves an already running server active; **Stop** shuts it down gracefully and preserves downloads for resuming.

The launcher uses Qt Widgets with antialiased system fonts, readable French and English text, blue checkmarks and two rows of five tabs. Folder selection uses native platform dialogs where available, including the GTK chooser on GNOME. No Chromium or Electron runtime is added for this configuration window.

### Desktop administration and recovery

Port selection, startup interface, download preferences, proxy settings, library backups and local diagnostics are available from the launcher. Browser recovery tools remain accessible if the native interface cannot open.

## Added

- **(Launcher)** Ten settings tabs: WebUI, Server, Downloader, Directories, Requests, Proxy, Extensions, Diagnostics, Backup and About.
- **(Configuration)** Persistent startup page, language, download folder, parallel transfer/media limits, bandwidth limit and request timeouts.
- **(Maintenance)** Port availability checks, server status, graceful restart/stop and redacted diagnostic reports.
- **(Backup)** Verified SQLite snapshots that include committed WAL data while the engine is running.
- **(Packaging)** Administration, Browser and Stop shortcuts, plus build provenance and third-party license notices.
- **(CI)** Real Windows launcher and Edge WebView2 rendering checks, packaged launcher checks and backup failure regressions.

## Changed

- **(Startup)** Opening the desktop executable shows the native launcher. `--launch` starts directly with saved preferences; `--headless` remains available for background use.
- **(Interface)** Native text rendering, scalable checkbox ticks, balanced tab rows and platform file dialogs replace the previous launcher rendering.
- **(Settings)** Existing libraries and download preferences seed the desktop profile; proxy credentials stay in the engine database and are excluded from exported launcher settings.
- **(Packaging)** Desktop builds include Qt Widgets and its platform plugins. Unused Qt WebEngine/QML/Quick modules and unrelated host icon/theme collections are excluded.

## Fixed

- **(Windows)** Native startup uses a valid ICO resource and works without console streams.
- **(Backup/Windows)** SQLite connections close before the snapshot is copied or deleted, preventing `WinError 32` and preserving the original error when a backup fails.
- **(Lifecycle)** Engine supervision, startup readiness, library locking and orphan recovery prevent duplicate or abandoned desktop engines.
- **(Launcher)** Accents and punctuation render correctly; tab titles remain readable and field values survive page/language changes.
- **(CI)** POSIX shortcut permission assertions run only on hosts that support Unix executable bits.

## WebUI

The compiled Vue interface and Python engine ship together. Choose Browser or the optional native WebView in the launcher, and open your preferred page at startup. The launcher can also open Sources and Extensions directly.

Download **one archive** for your platform, extract the entire folder and open its launcher. Python and Node.js do not need to be installed separately; FFmpeg and ffprobe are included.

**macOS packages are unsigned and not notarized.** Linux builds require compatible system libraries; see the desktop guide for GTK/WebKit dependencies and browser mode. Automated checks do not certify playback on every device or access to third-party sources.

**Updating:** stop AnimeLab using the old launcher or its Stop shortcut, then extract the new archive into a separate folder. Your library and settings remain in your user data directory. Do not delete that directory or overwrite a running installation.

[SHA-256 checksums](https://github.com/loeuf237/animelab/releases/download/v0.1.3/SHA256SUMS.txt) cover the four archives and their build-info manifests.
